# Design gaps (round 3, merged tier)

Where an SR obligation is not met by today's code: the SR, the merged LLR that now states the design, and what the code does instead. This list becomes the build work. It is the alignment's merged list (section 6, M01 to M57) with the coordinator's calls (r3-dispositions.md, K01 to K38, P-01 to P-07) applied, plus three gaps those calls add (M58 to M60). Round 3b (`../r3b-change-log.md`) applied the review dispositions: it amended M01, M10, M12, M32, M34, M51, M54, M55 and M60 in place where a disposition changed what governs them, and added M61 to M82. Round 3d (`../r3d-change-log.md`) applied full round 2: it amended M55, M62, M63, M64, M67, M73 and M79 in place and added M83 to M88. Round 3f (`../r3f-change-log.md`) applied full round 3, the last: it amended M64, M73, M83, M84, M85, M87 and M88 in place and added M89 and M90. Round 3h (`../r3h-change-log.md`) closed the design tier: it added M91 to M95. 'Found by' says which derivation listed it; the last column records the call or the code check that settles it. Nothing here was run; a 'does instead' resting on inference says so.

## 4. Code beyond the design

No SR asks for these. None is stated by an LLR; where the request form still accepts a switch so that existing callers are not refused, the interface form says so.

- **Removal dry run** (the removal's what-if switch, and the container's dry-run variable). P-02 default (c), K04: it stays accepted in the removal request form (IF-002) and the container form (IF-038) and keeps working, unspecified; no LLR states it, and it is never made a bad request until the Owner rules (add a need, or retire it with a release note).
- **Removal overrides at the module level** (discard unreferenced content, accept unverified records, skip verification). K06: not in the request form; SR-046 refuses those cases without exception. Retire them or keep them test-only.
- **The deep-check switch.** K05 proposed folding it into the default check; P-03 (b), 2026-10-18, keeps it with today's meaning (LLR-049, IF-002), so this is no longer a downstream-visible change.
- **The permission switch for obtaining the hashing component.** K07: accepted with no meaning; the component is fetched without a question (LLR-105).
- **The strict-evidence restore switch** (both routes). Kept in the restore request form (IF-020) and honoured in LLR-039, though no SR asks for it; treat like the dry run: the Owner adds a need or it stays outside the design.
- **The multi-set warning.** Goes (SR-095, LLR-014).
- **The run-date test seam** (the switch that pins a run's date). Round 3b (R3O-036): listed in the launch form (IF-002) as a test seam that sets the run's clock, so no caller is refused; still no SR asks for it and no LLR states it.
- **The include-saved-states boolean and the verify alias.** Accepted by today's entry point; the merged IF-002 lists both as accepted spellings of existing requests (latest-only check, the check action), so they stay working with no new meaning.
- **The listing location must be on the backup's volume.** K35, R3O-017: kept, and now traced to SR-062 in LLR-153 (each view entry is a relative link to its stored object, and a relative link cannot cross volumes on Windows), so it is no longer beyond the design.
